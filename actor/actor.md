### 액터는 왜 등장했는가?

참조 타입에서 발생하는 동시성 문제를 해결하기 위해서 등장했다. 액터 도입 이전에 동시성 문제를 해결하기 위해서는 `Lock` 이 거의 필수적으로 사용되었는데, 이것은 데드락을 발생시키기가 너무 쉽다.

---

### 액터는 어떻게 동작하는가?

Serial Executor라고 하는 직렬 실행자를 통해서 액터에 접근하는 작업을 큐에 넣어서 처리한다. 해당 작업들은 한 번에 하나만 실행되어 동시 접근을 막아준다. 이때 이 큐는 단순히 FIFO로 동작하는 것이 아니라, 우선순위를 고려하여 작업을 진행한다.

---

### 액터의 비격리는 무엇인가?

액터의 격리가 필요하지 않은 경우에는 액터의 비격리를 사용할 수 있다. 액터의 격리에 포함되지 않기 때문에 동시에 접근해도 문제가 발생하지 않는 데이터에 한해서 사용해야 한다.

```swift
actor Counter {
    nonisolated let clientID: Int
}
```

비격리 데이터는 액터로 격리되어 있지 않기 때문에 동기적으로 접근이 가능하다. 하지만 액터 내부에서 비격리 데이터에 접근하기 위해서는 격리 경계를 넘어가야 하기 때문에 `await` 을 사용해야 한다.

---

### 액터의 원자성은 무엇인가?

액터의 원자성이란 하나의 논리적 연산이 중간에 다른 작업의 간섭 없이 수행되는 것을 의미한다.

다음 코드는 원자성을 보장하지 못한다.

```swift
actor BankAccount {
    private var balance = 100

    func withdraw(_ amount: Int) async -> Bool {
        guard balance >= amount else {
            return false
        }

        await Task.yield() // 1

        balance -= amount
        return true
    }
}
```

그 이유는 `1`번 코드에서 Suspension Point가 발생할 수 있기 때문이다.

액터는 한 번에 하나의 작업만 실행하지만, 실행 중인 작업이 중단되면 다른 작업이 액터에 진입할 수 있다. 이를 ‘액터 재진입성’이라고 한다. 따라서 중단된 작업이 재개되었을 때 `balance`가 이전과 동일하다는 보장은 없다. 이미 확인한 출금 조건이 더 이상 유효하지 않을 수 있는 것이다. 그렇기 때문에 액터의 원자성을 유지하려면 논리적으로 하나의 연산이어야 하는 구간에 Suspension Point가 존재하는지 확인해야 한다.
